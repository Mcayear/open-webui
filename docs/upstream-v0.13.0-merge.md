## 冲突与构建约定

两个内容冲突分别为 README 与 `vite.config.ts`。README 采用上游重写后的结构，将 DeepSeek 配置说明放入独立章节；Vite 采用上游 ES2022 目标、依赖预构建目标和 noVNC 许可证复制，保留 slim 构建关闭 source map 的仓库定制。

检查全部生产 `_app/immutable` JS（包含 worker）时，发现旧的 `esbuild.pure` 仍留下 7 处 `console.log`：包括返回值表达式、日志回调及第三方代码。将压缩器改为 Terser，通过 `compress.drop_console: ['log', 'debug']` 选择性移除；`ENV=dev` 时保留日志，生产继续保留 `console.error`。新增直接开发依赖 `terser==5.51.2`，并将基于 TypeScript AST 的产物检查 `scripts/verify-production-logs.mjs` 接入前端 CI。检查实际调用节点，避免把字符串或注释里的日志示例当成调用。最终生产构建成功，全部产物共保留 668 处 `console.error`，`console.log` 和 `console.debug` 均为 0。

保留本仓库 GitHub Release、Docker 多架构发布、独立 slim 构建与缓存等发布定制；未将发布流程列作待上游修复缺陷。检查上一版标签发布运行 `40856111708` 确认镜像构建均成功，但上游 Helm 仓库通知因缺少 GitHub App ID 失败（`appId option is required`）。该上游专用通知现仅在 `open-webui/open-webui` 仓库运行，fork 继续正常构建和发布镜像。
